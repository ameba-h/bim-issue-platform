# 接入与通道口径

平台自带一层 MCP（Model Context Protocol）服务，AI 客户端**填一个 URL + 一枚令牌**就能连上。它随平台进程一起启动，**零额外部署配置、零新增环境变量**，也不需要单独跑一个进程。

薄壳只做协议翻译与转发：不 import 服务层、不查库、不做映射层，权限 / 冻结闸 / 幂等 / 留痕全部由 REST 那一层照咬。所以 REST 侧改了字段或规则，这一侧最多改工具描述文案 —— 它不会长成第二套业务规则。

## 怎么配

```
URL:    http://<平台地址>:<端口>/mcp
Header: Authorization: Bearer <个人 API 令牌>
```

令牌在**个人设置 → API Token** 里生成，明文只显示一次，重置即顶掉旧的。

| 客户端 | 配法 |
|---|---|
| Claude Desktop | 设置里的连接器，填 URL + 头 |
| Cursor | MCP 设置里加一个 HTTP 类型的 server，同上 |
| Claude Code | `claude mcp add --transport http bim-issues <URL> --header "Authorization: Bearer <令牌>"` |

客户端侧**不需要配任何 AI 相关的头** —— 是不是 AI 通道由服务端验密钥；交给客户端的那枚令牌也不需要特殊标记，它本身就是 MCP 专属凭据。

传输是无状态 Streamable HTTP：POST 直接回 JSON，GET 与 DELETE 回 405，服务端不维持会话。全部工具都是「一问一答」。

## 令牌只能走这一条路

**令牌 = MCP 专属凭据。** 拿它直连任何 REST 端点（**GET 也算，自己写脚本也算**）一律 `403 TOKEN_AI_CHANNEL_ONLY`，读写皆拒。

理由是两头：直连读会暴露操作记录与成员这类敏感面；直连写可以伪造归因。**「一人一 token」的口径不变**（身份全局一个、不携带权限），变的是通道定性 —— 令牌是给 AI 用的，**人查数据用网页**。

这道闸由一枚**只活在内存里的进程内密钥**强制：薄壳转发时额外带一个密钥头，不进环境变量、不落盘、不下发客户端。闸口对一切令牌请求逐字比对，带对 = 来自薄壳，没带或带错 = 直连，拒。新增端点默认落在闸内。

## 三个身份怎么落

| 怎么进来的 | 留痕通道 | 三个身份 |
|---|---|---|
| 网页（会话 Cookie） | `web` | 人本人；发令人与代理两格空着 |
| **MCP（AI 客户端）** | **`ai`** | 操作者 = AI 助手 · 发令人 = 令牌主人 · 代理 = AI 助手；数据出身标 `ai` |
| 令牌绕过薄壳直连 REST | —— | 读、写一律拒（见上一节） |

**标记是服务端注入的，不是客户端声明的。** 转发时强制带上代理执行那两样头，客户端自带什么声明都无效 —— 声明可以被伪造，而 AI 账户的编号从操作记录里就能读到，等于谁都能给自己贴或不贴标签。

## 权限与几条硬口径

- **权限 = 发令人权限 ∩ 该项目的 AI 允许动作清单**，是交集不是并集：AI 永远做不到发令人本身做不到的事。读不受清单约束（清单只管写），写只开放那几项。
- **关闭 / 重开问题永远拒**，引导人去网页点。这是口径不是缺陷。
- **删除一律降级成待删清单**，一行不动、一条不留痕；人确认之后由人自己的凭据再发一次才真动。
- **库里没有在用的 AI 账户时，写操作全拒（fail-closed），读照常放行。** 宁可拒也不回落成「记在令牌主人自己名下」—— 那是把 AI 的操作误归因给一个具体的人。管理员建好或恢复账户之后**下一发即恢复，无需重启**，所以「停用 AI 账户」就是 AI 写侧的总开关。
- **新加的权限动作对既存项目默认是关的**：「默认全给」只在项目新建或从未保存过设置时成立；负责人保存过一次，库里存的就是当时勾的显式清单。所以 AI 打某些项目会吃「这个动作不允许」，那是预期，出路在服务端那句话里（联系负责人去项目设置勾选）。
- 幂等键薄壳自动生成（每次批量调用一枚），契约里「批量真跑必带」这件事对模型是透明的。预演模式不消耗幂等键。

## 接不通的时候先分三件事

1. **先认清是「认不出这串」还是「认得出但通道不对」**：前者说明令牌本身坏了（或根本没发出去），后者说明令牌是好的、只是被拿去直连 REST 了 —— 那永远不可能成功，最多换来一句「仅限 AI 通道」。客户端如果拿「读我自己的信息」当健康检查，探针选错了，**该打 `/mcp` 的工具清单**。
2. **这个平台没有「有效期」概念**：令牌不会过一阵自己失效。谁说令牌过期了，让他先给出这条令牌最后一次被使用的时间。
3. **「令牌无效」最常见的根因在客户端那一侧的执行通道**：有些客户端会把命令里出现的令牌自动脱敏成 `***` 再发出去，发出去的本来就是坏串。排查办法是让请求头从文件里读，别在命令行里拼。

## 已知边界

薄壳不做限流（量级摆在那：四到十五人的内网）。多维筛选在工具参数上只取单值，要「或」的语义就发多次查询。

工具清单与逐个工具的行为差异见 [工具清单](/mcp/tools)；接口的字段、错误码、响应结构一律看 [API 契约](/reference/api) —— 那才是工具定义的唯一事实来源。
