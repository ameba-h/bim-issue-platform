# 工具清单（17 个）

全部工具 **1:1 对应契约端点**，薄壳只做参数模式 + 转发 + 描述文案。接入方式见 [接入与通道口径](/mcp/access)。

## 🗂️ 项目与类目

| 工具 | 干什么 | 要点 |
|---|---|---|
| `list_projects` | 我参与的项目 | 零参数。从返回里取 `projectId`（26 位项目 ID，之后所有工具都传它）、`code`、`name`、`role` |
| `list_tags` | 四维度分类体系 | 类型 / 专业 / 专项 / 子项分组返回。挂标签用的编号**只能从这儿来** |

## 📌 问题

| 工具 | 干什么 | 要点 |
|---|---|---|
| `search_issues` | 查问题列表 | 状态 / 重要程度 / 出身 / 关键词 / 标签 + 排序 + 分页（默认一页 50，上限 200）。总条数看 `page.total` |
| `get_issue` | 单条完整详情 | 含答复与附件 |
| `create_issue` | 建问题 | 附件随参数走（Base64）：单次 ≤6 个、单个 ≤10 MB；图片自动判成「截图」，其余判成「过程附件」；重要程度缺省取普通；执行人默认 = 令牌主人 |
| `update_issue` | 改字段 | 标签支持全量替换与增删两种写法；传了但真无变化会明确回「无变化」；已关闭的问题只放行改执行人；改执行人只有负责人能做 |
| `change_issue_status` | 关闭 / 重开 | **AI 通道一律拒**。留着这个工具只为让调用方拿到一句明确的拒绝原因，而不是「找不到这个能力」 |
| `batch_update_issues` | 批量改 / 批量删 | 删除经 AI 通道降级成待删清单；支持预演；**必须读回每一条的失败原因** |
| `add_reply` | 加答复 | 带图同建问题那套尺寸闸；答复只增不改不删 |
| `get_stats` | 各维度计数 | **零条的类目也会回一条 0**；各维度之和可以大于总数，属设计不是重复计数错 |
| `export_issues` | 导出问题清单 | 回**10 分钟内有效的签名 URL**，不返回文件内容。智能体用 HTTP GET 自取（不带任何凭据头）、自行转交发起人；量大时 429「稍后再发」（任务没丢）；权限与网页导出同闸 |

## 📝 说明板块

| 工具 | 干什么 | 要点 |
|---|---|---|
| `get_sections` | 读说明板块 | 概况 + 各专业设计说明全量回读，条目带出身与最后编辑人 |
| `put_section` | 写说明板块 | **覆盖式**：唯一键 = 项目 + 板块类型 + 专业，命中就改、没命中就建。需要「撰写说明板块」这一项权限 —— **一个动作同时罩概况与设计说明两类**：权限按方法 + 路径判，薄壳没有也不该有第二把闸 |

## 📈 经济技术指标

| 工具 | 干什么 | 要点 |
|---|---|---|
| `get_metrics` | 读指标 | 按组回读，条目带出身与最后编辑人 |
| `create_metric` | 建指标 | 只有两级（第二级是「其中：」子项）；数值是**纯文本**，薄壳不做单位换算；不写排序就追加到组尾；需要「撰写经济技术指标」权限 |
| `update_metric` | 改指标 | 只传要改的字段；同值回「无变化」；**出身列不翻**（AI 写过的内容改完仍标 `ai`） |
| `delete_metric` | 删指标 | **经 AI 通道不真删** → 回待删清单，一行不动、一条不留痕，人确认后再发同一发才物理删 |

## 🚫 刻意不进薄壳的三类

接手的人别当遗漏报回来：

- **附件的独立上传端点** —— multipart 那条路已并入建问题与答复；
- **成员与平台管理** —— 权限敏感且模型用不上；
- **冷门筛选参数** —— 用到再加，加的时候只改描述与参数模式。

导出曾经也在这份名单里（理由是「文件回不到模型手里」）。那个理由针对的是**模型读文件**，而放开的形态是**运行时取文件**：`export_issues` 回签名链接，下载由智能体的 HTTP 能力执行，二进制一个字节都不进模型上下文。

## ⚡ 三条容易踩的行为差异

- **删除是「待删清单」不是真删。** 问题软删可复原；指标表没有软删列、真删就是物理删 —— 所以指标那一道降级更不是装饰。
- **AI 写过的内容，人接手改也不翻出身标记。** 出身列保持 `ai`，这是留痕口径，不是 bug。
- **库里没有在用的 AI 账户时，读照常放行、写全拒。** 停用 AI 账户就是 AI 写侧的总开关，恢复后下一发即通，无需重启。
