# 配置与部署

> 这一页讲四件事：`.env` 里每颗开关管什么、两种数据库怎么选、部署形态各自的运维要点、数据和备份的规矩。怎么把平台第一次跑起来，看 [快速开始](/guide/getting-started)。

## ⚙️ 环境变量（`.env`）

以 `.env.example` 为模板复制为 `.env`（不入库）。**代码真正读取的就下面这些**，别处出现的变量名都不生效。

### 数据库

| 变量 | 说明 |
|---|---|
| `DATABASE_CLIENT` | 选库：`sqlite`（默认推荐）/ `mysql` |
| `DATABASE_FILE` | SQLite 库文件位置，默认指向 `data/` 下那份；老别名 `DB_FILE_NAME` 也认，**同时存在时以前者为准** |
| `DATABASE_HOST` / `DATABASE_PORT` / `DATABASE_NAME` / `DATABASE_USERNAME` / `DATABASE_PASSWORD` / `DATABASE_URL` | MySQL 连接信息。密码含 `#`、空格等特殊字符时**必须用双引号包裹**（不加引号会被当行内注释截断） |
| `MYSQL_BIN` | 建 MySQL 库时用的命令行工具位置，不设则去 PATH 里找 |

### 会话

| 变量 | 说明 |
|---|---|
| `NUXT_SESSION_PASSWORD` | 登录会话的加密密钥，**≥32 字符随机串**。开发期不设置系统会临时生成一个，但换掉这串会让所有已登录的会话失效；生产必须显式配置 |

### 落盘位置与模型解析

| 变量 | 说明 |
|---|---|
| `UPLOAD_DIR` | 截图、附件、头像、模型与解析产物的落盘根目录，默认 `data/uploads/` |
| `EXPORTS_DIR` | 导出产物根目录，默认 `data/exports/` |
| `IFC_PYTHON` | 解析 IFC 用的 Python 解释器，不设则依次试 `python` / `python3` / `py` |
| `IFC_CONVERTER` | 转换器脚本位置，默认 `scripts/ifc/ifc_2_snapshot.py`；指到别处时**同目录必须放着那份快照口径文件**，否则永远解析不出内容 |
| `IFC_PROBE_TIMEOUT_MS` | 探测解析环境的超时，默认 8 秒；一般只在本地验证时用 |
| `MODELS_TOTAL_LIMIT_BYTES` / `EXPORT_VOLUME_LIMIT_BYTES` | **只用于本地验证**：临时压低「一整套模型合计」和「导出单卷体积」那两道闸，生产不要设 |

### 端口

端口**不在上表**，因为平台代码不读它：开发端口固定 **5555**（定义只在 `nuxt.config.ts`，不要另挑）；生产由运行时的 `PORT`（或 `NITRO_PORT`）决定——标准包在 `.env` 里配，绿色包在启动脚本里（见下文，要改两处）。

### 两条纪律

- **`.env` 没有热通道**：所有变量都是进程启动时读一次，**改任何一颗都要重启服务**才生效；
- **想把破坏性试验隔离开，就三颗开关**：`DATABASE_FILE`（库）+ `UPLOAD_DIR`（上传根）+ `EXPORTS_DIR`（导出根）——把这三样指到副本目录，怎么折腾都不碰真数据。

**凭据红线**：真实口令 / 连接信息只存本地 `.env`；仓库（含文档、脚本、源码）一律不留明文。若部署到公网或共享环境，请务必使用强口令。

## 🗄️ 数据库选择

### SQLite（默认，推荐单机 / 小团队）

- 零配置，一个文件即一个库（`data/` 目录），备份 = 拷文件；
- 走 Node 内置 `node:sqlite` 驱动，**无任何原生编译依赖**；
- **注意**：SQLite 是单文件库，所有人共用完全没问题 —— 大家的操作都经过同一台机器上的平台服务，并不直接碰这个文件。真正要避开的是两种用法：**同时跑多个平台实例去指同一个 `.db`**，或者**把 `.db` 放网络共享盘让几台机器分开跑** —— 网络文件系统的文件锁不可靠，可能损坏数据。确实要多台机器共同供一套数据、或要接公司现成 MySQL 的，就切 MySQL。

### MySQL（多人共享 / 接入既有基础设施）

- 面向 MySQL 8.0+ 设计，字符集 `utf8mb4`；
- 建库用 `pnpm db:init:mysql`（需要先手工建库与账号，见 `scripts/db/00_init_database.sql`）；
- 应用账号建议**只授予本库权限**，不要用 root 连库；
- **改过表结构后重建，必须先把全部旧表清掉再跑** —— 建库 SQL 只建不改，对着已存在的表什么都不动，不清表的症状是「不报错、但数字还是旧的」；
- 部署包场景：标准包只带纯建表脚本（`01_schema_sqlite.sql` / `01_schema_mysql.sql`），用你自己的数据库客户端执行；仓里的远端初始化脚本**绑的是开发环境**，不要拿去连现场的 MySQL。

### 切换与迁移

两库共用同一套表定义（`server/database/schema.ts` / `schema.mysql.ts`）与迁移脚本，切换只需改 `DATABASE_CLIENT`。表结构变更流程见 [数据库设计](/reference/database)。

## ▶️ 初始化命令

| 命令 | 作用 |
|---|---|
| `pnpm db:init` | SQLite 建库 + 建表 + 自动创建默认平台管理员（幂等 —— 库里已有管理员则跳过，**不会覆盖已有口令**） |
| `pnpm db:init:mysql` | MySQL 建表 + 同上（幂等） |
| `pnpm db:migrate` | 执行尚未应用的表结构迁移；按库里的迁移记账决定跑哪几条，重复跑不会重放 |
| `pnpm db:check` | 把几份表定义互相对拍，防漂移；**改过表结构必跑** |
| `pnpm db:seed-tags` | 给已有项目补灌 41 项标准分类（`--project <ID>` / `--all`；支持先预演再执行；只补缺、不改不删） |
| `pnpm user:create` | 建一个真实账号；加 `--username <名> --reset-password` 可交互式重置已有账号口令（不进命令行历史） |

## 🚀 部署形态

三种跑法（绿色包 / 标准部署包 / 源码）的**上手步骤**在 [快速开始](/guide/getting-started)，这里讲各自的运维要点。

### 绿色包（Windows 一台机，免安装）

- 首次双击 `启动.bat` 依次发生：自动生成配置（SQLite 档 + 随机会话密钥，已有则跳过）→ 检查库（**包内已带演示库，这一步直接跳过**；没有才建空库并在窗口打印初始口令）→ 打印本机与局域网地址并开浏览器 → 前台跑服务（**窗口关掉 = 服务停**，最小化没问题）；
- 长期运行用 `安装为开机自启.bat`（注册为 Windows 计划任务，不装任何第三方），之后无窗口后台跑、日志进 `logs\service.log`；
- ⚠️ 要改端口得**改两处**：`启动.bat` 与 `service-run.bat` 里各有一颗端口设置，只改一处会出现「手动起在 5556、自启还在 5555」；
- ⚠️ **开机自启与模型解析有冲突**：自启任务跑在 SYSTEM 账号下，只有系统 PATH，**看不见当前登录用户装的 Python 包**——「双击启动那格是绿的、注册自启后变红」是真实形态。两条出路：把解析依赖装到 SYSTEM 也看得见的全局位置，或把自启任务的运行账号改成装包的那个用户。

### 标准部署包（团队 / 服务器，跨平台）

- 唯一要手动做的是装 Node（**≥ 22.9**）；`run.bat` / `run.sh` 是自举的：缺配置自动生成、缺库自动建，然后起服务；
- 首启建的是**干净空库**（不带演示数据；要看示例项目请用绿色包），默认管理员的初始口令在启动窗口里打印；
- 要接 MySQL：`.env` 改 `DATABASE_CLIENT=mysql` 填连接信息，建表脚本手工执行（见上文 MySQL 一节）；
- Linux 常驻用包内 `bim-issue.service` 示例（systemd）；
- ⚠️ **模型解析在 Linux 侧尚无实测**——上去之前先拿一套真模型跑一遍解析、核对解析结果没问题，再交付给现场。

### 模型解析环境（Python，可选）

不装 Python，平台照样跑：模型的上传、存储、删除全部正常，只有解析不出数。**装不装，归这台机器的使用者决定**——平台管理员这个角色只管界面里的事，碰不到这台机的文件系统。

要装的话，两步：

1. **装 Python（3.10 ~ 3.15）**：官方安装包，安装第一屏**勾上「Add python.exe to PATH」**，不勾后面找不到人；⚠️ 别用 Microsoft Store 里那个 `python`——命令在、进程不干活，看着像装了其实等于没装。装完 `python --version` 能报版本再继续；
2. **装解析包**：`python -m pip install ifcopenshell==0.9.0`。版本号写死是有意的：转换器按这一版的行为整理，换版要先拿真模型核完数字再说。

连不上外网的机器：在能上网的同版本 Python 机器上 `pip download --only-binary=:all: --platform win_amd64 --python-version <目标机的版本号> -d wheels ifcopenshell==0.9.0` 把包连同依赖共 9 个拉下来，整个目录拷到目标机，再 `python -m pip install --no-index --find-links wheels ifcopenshell==0.9.0`。⚠️ `--python-version` **必须选对目标机的 Python 版本**（3.11 的机器写 `311`）——选错了装不上，报错看着像包坏了其实是版本没对上，这条是这一步最常踩的坑。

装完对着界面那一格判断（只有「缺依赖」会自己变绿）：

| 状态 | 意思 | 要做什么 | 做完要不要重启服务 |
|---|---|---|---|
| 绿 | 一切就绪 | 直接传模型 | 不用 |
| 缺解释器 | 找不到会答话的 Python | 装 Python（或改指路径） | **要**——正在跑的服务带着旧 PATH，看不见新装的 |
| 缺依赖 | Python 能用，包里没那个解析包 | 只补第 2 步那条命令 | **不用**，最迟 30 秒自己变绿 |
| 缺组件 | 平台自己的两份转换文件没在位 | **跟 Python 无关**，补齐 `scripts/ifc/` 那两份（必须同目录） | 改了环境变量就要 |

命令行想先自查：`python -c "import ifcopenshell; print(ifcopenshell.version)"`。另外记住两条：**装好之后旧失败的模型不会自动补算，重传原始图纸才会重跑**；改 `IFC_PYTHON` / `IFC_CONVERTER` 任何一颗都要**重启服务**才生效（没有热通道）。

### 局域网部署（最常见）

一台常开的主机（Windows 或 Linux 均可）跑起平台，其他同事使用浏览器访问 `http://<内网IP>:5555`。注意：**明文 http 地址下，浏览器会禁用一批能力**（涉及剪贴板那类操作），部分体验受限属正常现象，不是平台坏了。

### 外网部署

- **平台不强制加密**：任何地址形态都照常跑，加不加 HTTPS 由部署者自己决定；
- **但建议自备 HTTPS**：登录口令和令牌走公网时，明文传输有被窃听的实际风险；套一层 Nginx / Caddy 做 TLS 终结即可（应用本身同源，没有跨域问题）；
- 自行上代理时**只有一条硬规矩**：上传一整套 IFC 模型的合计闸是 **8 GB**，代理的请求体上限必须高于它，且要**关掉请求体缓冲**——否则整套字节会先在代理磁盘上落一份临时文件，撞线后用户看到的是一页报错而不是一句提示；
- 证书从哪来、域名怎么管，平台不提供随包方案，按你自己的通用运维做法处理即可。

### 进程常驻

Linux 用 systemd（标准包自带示例单元）；Windows 用绿色包自启任务，或计划任务 / NSSM 均可。给装机的人一句忠告：**部署必须做到「关掉窗口服务也不停」**——使用平台的人大多是非运维人员，顺手关掉终端窗口的同时平台就下线了，而且无人知晓。

## 📁 数据目录与备份

```
data/
├─ bim_issue.db                  # SQLite 库
├─ uploads/<项目ID>/             # 按项目分层的文件存储（⚠️ 目录到「类别」为止，文件名 = 记录 ID，没有日期层）
│   ├─ issues/<记录ID>.webp      # 问题截图（兜底转 WebP 后存）
│   ├─ thumbs/<记录ID>.webp      # 缩略图（不入库，按记录 ID 推导）
│   ├─ attach/<记录ID>.<ext>     # 过程附件（原样存，不压缩不转码）
│   ├─ cover/<项目ID>.<ext>      # 项目封面（文件名是项目 ID，单张替换即覆盖）
│   ├─ models/<记录ID>.ifc       # BIM 模型本体
│   └─ parse/                    # 解析库 + 状态旁文件 + 改名名单
├─ uploads/avatars/<用户ID>.<ext>  # 用户头像（用户级，不带项目 ID）
├─ uploads/.incoming/            # 上传暂存区（半截文件的家）
└─ exports/<项目ID>/日期-时间[-序号]/  # 导出产物（只有这一族有日期目录；启动时清扫）
```

**尺寸闸**（算备份盘之前先看）：

| 对象 | 上限 |
|---|---|
| 过程附件 | 单件 10 MB，单次最多 6 个 |
| 头像 | 5 MB |
| IFC 模型 | 单件 200 MB，单次最多 60 个，**一整套合计 8 GB** |

**备份要点**：

- **数据库与 `data/uploads/` 必须成套备份**，只备 `.db` 等于没备 —— 文件本体不在库里，库里只有元信息；
- 磁盘预算要留余量：覆盖上传一套模型时，**盘上会同时存在新旧两套**（峰值按 16 GB 算），解析产物还能到 GB 量级；
- 目录第一层就是项目 ID，可按项目粒度备份 / 迁移；路径用内部不可变 ID 而非项目编号——项目改名不影响已存文件；
- `exports/` 是派生物，不备也行：**导出产物在每次服务启动时清扫一遍**，常驻期间只增不减、重启即清，重跑一次导出就能重生；
- **删除的规矩**：问题、附件、头像在任何通道都只软删、磁盘永久保留；只有三样会物理删——导出产物（启动清扫）、上传中断的半截文件、IFC 模型及其解析产物（整套删除）。

## 🔒 安全清单（上线前过一遍）

- [ ] 默认管理员**首次登录立即改密**（初始口令只在首启窗口 / 包内说明文件给出，任何文档都不张贴）；
- [ ] `NUXT_SESSION_PASSWORD` 使用 ≥32 字符随机串（不要用示例值）；
- [ ] 外网访问建议自备 HTTPS（平台不强制，但明文过公网有窃听风险）；
- [ ] MySQL 部署时应用账号仅授予本库权限、不暴露公网；
- [ ] `.env` 不进版本库（已在 `.gitignore`，确认部署流程也不会带出去）；
- [ ] `uploads/` 目录不被静态暴露——所有文件访问都过接口鉴权、下载一律带 attachment 头，**不要额外配静态目录映射**。
