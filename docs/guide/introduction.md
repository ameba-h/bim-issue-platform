# BIM 问题管理平台 · 项目介绍

> 本站是面向使用者与二次开发者的整理版文档，只写现行口径 —— 已定的事直接写结论，当初怎么定的走仓库 git 历史查。日常使用与二次开发以本站为准。

## 🧭 这是什么

**BIM 问题管理平台**是一个面向建模阶段 BIM 工程师的问题（碰撞、图面错误、净高不足等）跟踪管理平台：

- **中小团队私有化部署**：装在公司内网或一台云主机上即可使用，支持 Linux / Windows；
- **为 AI 而生**：平台自带 MCP Server（随平台启动，不用额外装任何东西），AI 客户端填**一个 URL + 一枚个人令牌**就能接入，批量建问题、规范化描述、写答复、发起导出都做得到 —— 这是它与传统问题台账工具最大的差别。
- **多项目、多角色**：一个平台承载多个项目，项目负责人 / 专业负责人 / 工程师 / 甲方 / 协同方各按权限协作；

## 🎯 解决什么问题

| 痛点 | 本平台的应对 |
|---|---|
| 十个人记录十种写法，清单收到手先要「翻译」 | 问题按**六要素**模板记录（楼层 → 图纸 → 位置 → 结论 → 详情 → 建议），再按重要程度 / 类型 / 专业 / 专项 / 子项**五个维度**归类，谁记都是同一个格式，汇总与追溯不用手工对齐 |
| 一次面对几百条问题，认不出哪几条今天必须处理 | 首页就是汇总报表：未关闭几条、紧急几条、集中在哪一类自动分好，四种图一眼分辨；重要程度分四档（紧急 / 普通 / 轻微 / 建议），紧急判定有十三条硬约束 —— 由规则判，不由谁嗓门大判 |
| 想让 AI 帮着记录 / 批量处理，但平台没有 API | 全部业务能力开放为 REST API；AI 用各人的令牌走平台内置 MCP 通道**代理执行** —— 权限就是发令人在该项目的权限，AI 改过的内容一律带标记、写清是谁让它做的；删除只生成待删清单，需本人确认才真动 |
| 记录载体五花八门（Excel / Word / 各家平台），甲方收到三种格式的同一件事 | **三档导出**各有用途：带图 HTML 报告（ZIP 打包）用于成果归档、可直接打印成 PDF；Excel 用于外发统计与清单汇总；Word 用于过程讨论。对方不开本平台、不装额外软件就能看全（含图） |
| 团队没有专职运维，「装不上 = 平台不存在」 | Windows **绿色免安装包**：解压双击即跑，包内自带 Node 运行时，默认附示例项目；数据库默认 **SQLite 一个文件就是库**，多人共用或接公司现成 MySQL 时改一行配置切换 |

## 🧩 功能总览

- **问题管理**：
  - 创建：截图直接 `Ctrl+V` 粘贴即传，也可拖拽文件、随问题挂过程附件；
  - 筛选：按状态、重要程度、分类等条件筛选，服务端排序、分页；
  - 批量操作：一次改状态 / 改分类 / 改重要程度 / 改派执行人 / 删除（单次最多 500 条）；动手前可以先预演一遍 —— 不真改，先列出每一条会被改成什么样，看清楚了再执行；
  - 状态流转：问题只有未关闭 / 已关闭两态，只有执行人能关闭和重开；
  - 答复讨论：问题下方可答复讨论，答复也能带图。
- **汇总报表**：
  - 看什么：未关闭几条、紧急几条、集中在哪一类，项目问题什么样进来就知道；
  - 怎么分：按类目自动分组，总数加四种图一眼分辨；
  - 口径联动：报表与问题列表共用同一套筛选条件，筛完看到的和汇总出来的是同一份账。
- **文件管理**：
  - 截图：统一转 WebP 存储并生成缩略图；
  - 过程附件：Word / PDF / DWG / 压缩包等原样存储，只提供下载；
  - 图像：项目封面、用户头像；
  - BIM 模型：IFC 可上传，服务端离线解析后提供「IFC 画像」（开发中……）；
- **项目说明**：
  - 概况与指标：项目概况、经济技术指标（一行一指标，可分组排序）；
  - 设计说明：各专业设计说明用 Markdown 撰写，渲染展示；
  - AI 联动：全部字段开放 AI 读写，AI 写入显著标注。
- **项目设置**（仅负责人 / 专业负责人可进）：
  - 项目参数：改项目名、上传 / 移除封面、AI 允许动作开关（项目编号不可改）；
  - 成员管理：加人 / 改角色 / 移出 / 复入；
  - 分类体系：41 项标准分类建项目时自动初始化，可增可改。
- **平台管理**（平台管理员专属）：
  - 建项目：同时指派负责人、生成 `YYYY-NNN` 编号；
  - 账号管理：建号 / 停用 / 重置密码 / 平台角色；
  - 冻结与恢复：冻结 = 成员侧写操作全关，看东西不受影响。
- **操作记录**：
  - 记什么：全站写操作留痕 —— 谁（实际操作者）、受谁的指令（发令人）、何时、把哪个字段从什么改成什么；
  - 看得懂：AI 通道来的操作一眼可辨。
- **个人中心**：
  - 账号资料：资料 / 头像 / 改密；
  - API Token：一人一枚，库里存哈希、重置即吊销；它是 **MCP 接入专用凭据**，拿去直连 REST 会被拒。

## 🛠️ 技术栈

| 层 | 选型 |
|---|---|
| 框架 | **Nuxt 4**（全栈：`app/` 前端 SPA + Nitro `server/` 后端） |
| 界面 | Nuxt UI v4（Tailwind CSS v4），页面壳基于官方 **Nuxt Dashboard 模板** 搭建 |
| 数据库 | **SQLite（默认，零配置，走 Node 22 内置 `node:sqlite`）** / **MySQL 8**（多人共享开发库或既有基础设施） |
| ORM | Drizzle ORM 0.45（跨方言，双 config） |
| 鉴权 | `nuxt-auth-utils`（sealed 加密 Cookie 会话）+ 个人 Bearer Token（**MCP 专属凭据**，直连 REST 一律拒） |
| 运行时 | Node.js ≥ 22 + pnpm 11 |

## 🚀 部署形态

- **Web 应用（B/S）**，私有化部署优先：局域网内网地址访问，或部署到有公网 IP 的服务器；
- **绿色免安装包（Windows x64）**：解压后双击启动脚本即可运行，并可注册为 Windows 开机自启任务，包内自带 Node 运行时，目标机器不用装任何东西；
- 默认 SQLite 零配置开箱即用；需要接入既有 MySQL 时改一行配置切换；
- 典型规模：单团队 4~5 人至十几人；主交付形态是局域网内网地址访问。
