# 设计决策记录（为什么这样设计）

> 本项目每个关键取舍都留了理由。这一页把重要决策按主题归成一份「为什么」：**定了什么 · 为什么 · 代价是什么** —— 代价一栏从不省略，因为几乎没有一条决策是不付代价的。想改某处行为之前先看这里，多数「看起来奇怪」的实现都是有意为之；被拍过的事实只写现行结论，不写中间转过几个弯。

## 🧭 立项与总路线

### 为什么 REST 是唯一入口，MCP 只做薄壳

所有能力（包括 AI 用的）都走同一套 REST 端点，权限、校验、留痕只实现一次；MCP 那层只翻译转发。**这条的推论就是产品的安全承诺：AI 能做的事，永远不可能比一个有同样权限的人做的事更多。** 代价：放弃了 MCP 原生资源 / 订阅那套形态，且 REST 改字段时薄壳要跟着改描述文案。

### 为什么私有化部署优先、不做单机离线软件

目标用户是 BIM 工程师：装一个 exe 反而是负担；B/S 一套代码同时覆盖内网与外网两种场地。架构上「能转 SaaS」只做到配置能分开的程度，多租户没做，也不打算现在做。

### 为什么计划开源就必须 Linux + Windows 双平台，且依赖只允许纯 JS

开源与双平台是立项时的硬要求。它压出一条长期纪律：**禁止一切需要本机编译或下载平台二进制的依赖** —— 使用者是工程师不是运维，装不上编译工具链等于平台不存在。于是 SQLite 走 Node 内置驱动、口令哈希用内置 scrypt、图像处理用纯 JS、WebP 走 wasm；连端到端测试都只驱动系统里已装的 Chrome，不下载浏览器二进制。

### 为什么第一版就是「全部端点做完」

分两批只是节奏，不是砍范围。导出不是加分项，**是采纳门槛** —— 导不出符合行业习惯的交付物，团队根本不会换过来；经济技术指标是演示「AI 自己抓数据、分析、填进平台」的出彩点。这两项不许往后放。

## 🛡️ 权限与角色

### 为什么 AI 用「代理执行」单模式，而不是给 AI 独立账号权限

AI 在用户表占一行但**不能登录、不持有凭据、不加入项目**，唯一写通道是借人的令牌，权限 = 发令人权限 ∩ 该项目的 AI 允许动作清单。给 AI 一个「自己的角色」等于给系统开一条不看人的权限通道；而无人值守跑批的收益抵不上两套清单、两种权限算法、两套留痕形态的概念成本。三身份留痕字段都已就位，将来要做无人值守可加模式，不用推翻。不担心代理声明被伪造：这些声明**只会让权限变小**（取交集），不会提权，无恶意利用价值。

### 为什么「关闭 / 重开」只认执行人，负责人也不行

状态流转权绑定执行人而不是角色：负责人不改派就能关别人的问题，会让「执行人」形同虚设；而工程师对自己提的问题默认自任执行人，闭环成立。代价明说：负责人不是执行人就关不了自己名下没有的问题。

### 为什么甲方 / 协同方「可答复，但不可创建、不可导出、不能被指派为执行人」

可答复：外部参与方需要沟通通道，纯只读会造成大量线下往返。不可创建 / 导出：问题条目与全量清单是内部工作产品，导出权服务端直接拒，不只是隐藏按钮。不能被派成执行人是三条规则叠出来的死胡同 —— 「仅执行人能关」+「甲方即便被指为执行人也关不了」+ 派给外部人 = 这条问题**谁都关不掉**，所以建问题、单条编辑、批量改派三道口一律拒，界面候选人也从源头收掉。

### 为什么执行人必须是本项目的在册成员、且账号未停用

把活派给别项目的人等于破「项目数据物理隔离」那条判据 —— 以后让 AI 代理派错了人，是很严重的问题。界面下拉只列本项目成员、人踩不到，这一判防的是**直连接口那条通道**（人和 AI 代理都从那里进来）。停用的人同理：派给一个再也进不来的人，与派给外项目的人是同一种死局。代价：规则收紧前库里已有的这类历史行不受影响、照样关不掉，只能由负责人改派解开；这类判只拦新写入，真项目库上线时要当场盘一遍。

### 为什么平台管理员不管分类标准

平台级「标准模板表」会引出「已建项目是否跟随变更」等连环问题；改为**建项目时自动初始化 41 项标准类目**，之后归项目负责人 / 专业负责人维护。平台管理员职责收敛为：建项目、管账号、指派与移交负责人 —— 不因管理员身份自动获得任何项目内权限（他要看某项目的问题，得先被加成成员）。代价：跨项目没法统一分类口径（这是有意的）；「跨项目问题总览」这一格至今没做。

### 为什么专业负责人拆成两个值、权限却完全相等

拆分只为称谓与归属正确（土建 / 机电）。**纪律：判权时不得分成两个分支** —— 两者在代码里归并为单一「负责人能力组」。专业负责人可任命 / 降级同行、不必负责人在场，小团队少卡一层流程；唯一受限的是负责人那一行 —— 移交项目负责人只归平台管理员。错误码名沿用不改（改码等于破坏契约），语义收窄为「非负责人 / 非专业负责人想动成员角色」。

### 为什么界面隐藏按钮，而不是禁用按钮

甲方是外部用户，一排灰按钮只会反复来问「为什么不能点」。禁用态只留给「同一角色在当前对象状态下不可改」那一类（典型是已关闭问题的字段编辑），并且旁边必须写明那句话。

## 🗄️ 数据设计

### 为什么编号不复用、超限报错而不是扩位

问题编号 4 位、项目内递增、删除留空号：交付物上那个号是双方对账用的，必须短、可读、不重复。单项目上千条是常态、上万是峰值，超 9999 **显式报错**好过静默回绕造成两条问题同号。取号走项目行的计数器、事务内自增，杜绝「查最大值再加一」的并发重号；撞号不设静默重试 —— 曾经那段重试代码按约束名匹配，而多列唯一约束在 SQLite 报的是列名串，**它从来没生效过**，留着只会让人以为有这层保护。代价：单项目问题数硬顶一万。

### 为什么软删之后磁盘文件也永不物理删除（以及为什么附件传错了也删不掉真身）

问题记录是交付依据，删不掉才能追责；附件与问题绑定，文件同样只软删，否则「全量留痕」断在文件层。复核过「误传 / 涉密的图能不能真删」—— 拍板：不能，维持红线；单为「传错」开一条硬删，要动红线、还得配对照删除时间戳的清盘巡检，代价大于收益。例外只有三处：导出产物、上传中断的半截文件、IFC 模型与它的解析产物。代价也认下：软删留下的孤儿文件永久占盘，专门的清理至今没做。

### 为什么文件名用记录 ID，放弃哈希去重

同图去重需要引用计数（一条删除时另一条还指着同一个物理文件），复杂度不值当 —— 同图传两次的场景本来就少；而且哈希去重会让两条不同问题的同一张图指向同一个文件，与「附件随问题走」打架。文件名改用记录 ID 后每条独立存一份，删除零顾虑；哈希列降级为完整性校验与孤儿比对。

### 为什么文件路径用不可变 ID 不用项目编号

项目编号是展示物：可改名、可能在项目删除后被新项目复用 —— 一旦复用，新文件会落进旧编号目录，跨项目隔离从物理层被破；编号还是自由文本，没约束过文件系统安全字符。内部 ID 不可变，「改名 / 编号复用不影响已存文件」永久成立。「不好认」由界面解决：项目卡片同时展示编号与 ID，点击可复制。

### 为什么子表冗余项目 ID 并做复合外键

让「A 项目的问题挂 B 项目的类目」这种数据在**数据库层直接被拒** —— 不靠代码记得查，AI 批量灌数据也灌不坏。代价：SQLite 要求被指向列有唯一索引，于是多出三组「看似多余」的辅助索引，删掉就等于拆掉防护。

### 为什么类目不能删除、名称也不判重

删类目会让历史问题指向不存在的东西，所以不提供删除。类目名称**也不做判重** —— 判重的键只有缩写（维度内唯一）：类目是每项目自建的一套，重名由人自己分辨（列表里那两条的缩写与颜色不同），补一道名称判重要为一件不碍事的事新造一枚错误码，而错误码不自行新增。代价：同名两条会长期并存，看着像重复项 —— **这是拍过的口径、不是漏闸**。

### 为什么「当前项目」存服务端而不进 URL

换设备 / 刷新 / 多标签页全部一致，前端路由保持平层（`/issues` 而不是 `/p/:id/issues`）—— 项目上下文是账号级状态，不是标签页级。明确接受的代价：**两个标签页不能各开一个项目**（切一个另一个跟着变）；把某条问题的链接发给同事这一格，将来要做得单独加只读页。

### 为什么项目说明与指标单独成表

指标一行一条（可排序、带单位、让 AI 逐项读写「把总建筑面积改成 12.8 万」），塞进项目表等于每来一个新指标就改一次表结构。说明按（项目 + 板块类型 + 专业）唯一；专业那一列**概况存空字符串而不是空值** —— 两种库的唯一约束都允许多个空值并存，用空值「概况」能被插进第二条，约束形同虚设。

### 为什么枚举用字符串加检查约束、不用数据库原生 ENUM

保证 SQLite / MySQL 乃至换库兼容；加一个取值只改代码常量、不用发迁移。

### 为什么项目「冻结」不是「归档」

实际要的是「这项目别动了」，不是「塞进历史柜」：冻结 = 成员侧写操作全关、读都在；只有平台管理员能冻结 / 恢复。闸集中在请求包装器里判（写方法 + 项目路径即查状态），不是各端点各判一遍 —— 散着判必漏，漏一个就是「冻结了还能写」。两条豁免口写死在代码里：导出（归档的目的就是以后还要查）与移交负责人（那是平台管理动作）。代价：每个项目路径的写请求多一次状态点查。

## 🤖 AI 与数据写入

### 为什么 AI 写入免人工确认但要留痕标注

项目说明 / 指标类内容若每次 AI 写入都要人确认，AI 的效率优势就没了（「抓数据 → 分析 → 填平台」正是要演示的出彩点，加确认环节等于把出彩点变成体力活）。代价由**显著标注**（界面「AI 写入」徽标）+ **全量留痕**（操作记录里 AI 身份、发令人、时间、改动字段俱全）来对冲，核对责任推给读的人。问题侧更严格：AI 只能动清单内的动作，删除一律降级为「待删清单由人确认」—— 指标表没有软删列、真删不可回滚，所以这道降级不是装饰。

### 为什么建问题不硬卡分类

服务端只硬卡「描述不能空」这一条，四个分类维度不填照样过。取向：**工程师建模时只需要一句简单描述就能把问题建进来，分类之后让 AI 按规范补上** —— 卡得越死，越少人用；这与「核心需求是 AI 帮懒得记录的工程师把一句话变成合格记录」直接对应。代价两条都认：「记录风格不统一」这条痛点在服务端没有硬保证，靠规范 + 界面引导 + AI 补录这三样软的；AI 补分类要自己挑出没有类目那些条（列表没有「未分类」过滤器，界面上也没有任何一处显示「未分类」—— 这一版不做，别在实现时顺手加）。

### 为什么 AI 允许动作清单不做历史回填

新加的动作只对新建或从未保存过设置的项目生效；老项目要开，由负责人在项目设置里重勾一次。负责人保存过一次，库里就该是当时勾的显式清单 —— 平台越过人去改他存过的设置，等于把「做减法」那份承诺反过来用。代价：新动作上线后有一段「AI 打某些项目吃拒绝」，**那是预期不是回归**。

### 为什么 AI 账户全局一个，不按项目开

每项目一个会让人以为 AI 有项目身份，与「AI 不持身份」矛盾。代价：单枚通道被滥用的影响面是全平台（靠发令人权限收）。

### 为什么令牌没有有效期、也不做回填轮换

令牌是「我」的延伸：一人一枚、全局身份、权限按项目现算（角色一变立即生效）、长期有效。这个平台**没有「有效期」这个概念** —— 令牌不会过一阵自己失效；也不会因为开关变动就悄悄换掉你的令牌。代价：不做限流，泄露只能靠本人回来重置（重置即顶掉旧的）。

### 为什么留痕要分「实际操作者 / 发令人 / 代理 AI」三个字段

「谁做的」与「谁的权限生效」是两件事。早期设计把「谁下令」和「谁留名」挤进同一列，导致「人在网页上操作 = 自己命令自己」的语义不通，修正为三字段分列。读法：谁做的看操作者；谁的权限生效看发令人，发令人空着就看操作者自己的角色。

### 为什么幂等键作用域是「实际操作者 + 键」，而预览不消耗键

幂等防的是「同一操作者的重试重复落库」。挂到发令人上会有 NULL 不受唯一约束的漏洞（人直连时发令人为空）。预览不落键不是图省事：「先预览再真跑」是同一人同键的两步（请求内容不同、指纹自然不同），预览若参与判定，正常用法会**必然**撞上那条本只防误重放的冲突。

## 🖼️ 文件与图片

### 为什么截图一律由服务端规范化（无损优先 + 体积守卫），前端不压图

实测三类样本（CAD 图纸 / 三维视图截图 / 手机实拍）：线稿类 WebP 无损能压掉大半且画质零损失，JPEG 对图纸反而变大还糊线；**实拍照片无损反而膨胀四成**（传感器噪点让无损编码效率极低）。所以判据不是「先猜这张是图纸还是照片」，而是**先无损、无损反而比原图大就自动退有损 q80** —— 一条体积守卫让图纸留住无损、实拍自动转有损，不必分叉。前端对截图不做画布处理（先压必然丢掉无损），只有头像那一路由前端裁成正方形。

### 为什么长边闸 1920 对全部截图类生效，不放宽

手机实拍在本平台使用场景占比不高，不值得为体积约 2.6 倍买单；闸只按长边一条判，不按来源分叉（分叉就得先猜来源，而来源在盘上判不准）。代价：要看细部的人得回原始文件。另有一条已知且拍板「先不管」的：EXIF 方向转正没有落点 —— 不当已办，也别当缺陷报回来。

### 为什么上传走「随问题一个请求」而不是先传图再建问题

暂存上传方案需要临时区、过期清理任务、逐张重试机制；改成单请求后这些全部消失。代价是失败要整体重传 —— 靠幂等键保证重试不重复建数据、前端提交前本地预检（单次 6 个 / 单个 10 MB）减少整体重传概率。**单次上限 6 个文件即由此而来。**

### 为什么图片访问必须过鉴权、不做静态目录

uploads 若静态暴露，知道文件名即可绕过「不能跨项目查看」的隔离（附件含未公开工程资料）。所有文件访问走接口鉴权；下载强制「作为附件」头 —— 允许内联会让上传的 HTML / SVG 变成存储型 XSS。

### 为什么过程附件限制 10 MB 且不做任何在线预览（含 PDF）

上限刻意设小，引导用户精简 —— 别把平台当网盘传无关内容。不做预览是免去给每种格式各自做一次渲染器，全部只给下载。类型走白名单（扩展名 + 文件头魔数双判，不信任客户端报的类型）。

### 为什么误传的图「删得掉入口、删不掉真身」

明细抽屉的附件区有「删除单个」与「追加附件」两个入口，问题级与答复级都挂。但删除是软删：不再出现在这里、也不会进导出包，**磁盘上的本体保留** —— 与问题不可真删是同一套可回溯哲学。两个入口判权条件不同（一个认「是不是我传的」，一个认「这条问题是不是我创建的」），界面得分开判。

### 为什么大模型上传不复用附件那条通道

框架自带的表单读法是全量缓冲，单件 200 MB、一次最多 60 件等于把 12 GB 塞进一个进程 —— 所以模型上传**自己接流**（字节流直接管道进磁盘、边写边算哈希）；IFC 是文本格式，判型也不能混进图片白名单；删除语义还相反（附件软删、模型硬删）。三条结构性差异 ⇒ 两条落盘路，别混成一条。

## 📤 导出

### 为什么是这三档、不做 PDF 档

甲方要的是完整清单：导出范围 = 筛选条件下的全部，不止当前页、不止已选。Excel 给外发统计与加工；带图网页档给成果归档（解压只有网页加图片目录，浏览器打开、**要 PDF 就打印成 PDF** —— 问题一多 PDF 直接导出会非常大，这一转交给浏览器最划算）；Word 小批量给过程讨论，一次上限 100 条、勾超了不自动翻页凑数。

### 为什么带图那档导原图、打 ZIP、还会切包

单文件内嵌编码会大三成且不好打开；交付方要能挑清截图，所以导原图。包体积按累计 3.5 GB 贪心切分（留余量确保成品小于 4 GB，Windows 自带解压能开），装包顺序按问题编号升序固定 —— 让人能核对哪个包装了什么。必须**后台任务 + 流式写盘**，禁止在同步请求里打包。代价：一次导出可能出多个包；**只能用浏览器打开，用 Word 打开图是红叉** —— 这句必须写进包里；最小切分单位是一条问题，单条自带图超阈值时那一片会很胖。

### 为什么 Word 档曾经纯前端组装、服务端零参与

只用两个已经接好的读口，加服务端那一路要为一种格式引一整条流水线。代价：100 条时浏览器要连着打上百次明细请求。搬进服务端（含给 AI 通道用）已在排期路上，版式定稿后以服务端那份为准。

### 为什么 AI 通道导出只回一条限时下载链接

产物是文件，字节不该过模型的手：服务端打好包回一枚 10 分钟内有效的签名链接，**由智能体自己发一次 HTTP 下载**再经它自己的渠道转发 —— 投递不归平台管。被否掉的形态：链接给人点（内网部署外地点不开）、平台自建投递（不归平台管）、整包字节回传（胀三成、撑模型上下文）。一字之差是分工：「模型读文件」不做，「运行时取文件」放开。代价：密钥只活内存，**服务重启换钥、旧链接全体作废**；量大时回「稍后再发」。

### 为什么过程附件不导本体

附件本体体积不可控，甲方要的是问题清单 —— 清单里报个名字。代价明说：「把整个项目打包给我」这一格没法满足。

### 为什么甲方与协同方连导出按钮都看不见

导出物是内部交付口径，外部要清单由负责人代导。第三档纯前端组装、没有端点可拦，所以「拒」落在**不给入口**这一层（前两档是服务端拒）；这两个角色的读口照旧开着 —— 那是协作必需的最低读权，不是漏闸。

### 为什么「同一秒第二十一发导出」回「稍后再发」而不是 500

打包目录名让路只有二十格，撞满那一发一个目录都不建、不登记任务。它是「请等一等再发」，不是事故，所以复用早就登记的那枚限流码、零新增。⚠️ 这不代表通用限流开做了 —— 内网小团队常态点不出每秒 21 发，这一枚目前只有一个抛点；但「人手点不出」只对鼠标成立，脚本与令牌连打是打得到的。

### 为什么 Excel 全量档的耗时记成已知代价、不改代码

本地 5~15 人、单项目几百到上千条的使用形态下无感。那一档是「一次取全量 + 内存里逐行重扫」，条数越大越钝（外推两千条约一秒、五千条约七秒、两万条按分钟算 —— 是外推，不是量出来的）。改成按批分组聚合要为一种够不到的量级重写取数；真到那个量级，先改的是重扫与回吐方式，不是加索引。

## 🧱 前端工程

### 为什么筛选条件不进 URL

条件存内存态，明确接受三条代价：**刷新丢、后退键直接退出列表页、链接不能复现筛选结果** —— 换来零成本、不污染地址栏。「刷新不丢」恰是地址栏的独占收益，取舍另一侧站不住；真需要时按标签页隔离补一层会话存储约三行即可。

### 为什么批量按钮「按角色粗判显隐、结果逐条反馈」

「仅执行人」「仅自己创建」本就逐条判定，按钮层无法跟着勾选预判；跟着跳变反而让人困惑。代价是提交后必须逐条展示成功 / 失败原因，不得只弹一句「已处理」—— 部分成功是这个接口的既定语义。

### 为什么不用随机数标准接口的默认写法生成幂等键

浏览器那个标准 UUID 生成函数按规范只在 https 与 localhost 存在，而主交付形态是**内网明文 http**，那里它是「不存在」。所以用低一层随机数手拼 —— 幂等键要的是唯一，不是密码学不可预测。同一类坑在剪贴板上也踩过（明文 http 下没有剪贴板接口，要靠第二条路兜）。**由此立了一条纪律：凡是浏览器能力，先问一句「内网 http 下它在不在」。**

### 为什么图片 blob 化且不做缓存

直接把接口地址挂进图片标签，失败时只显示破图 —— 分不清「无图」与「无权」，做不了占位与统一错误处理。每次显示重新拉取、用完释放：缓存必须管「何时销毁」，时机错了是内存泄漏，出错代价高于重复下载（内网传输量可忽略）。

### 为什么界面文案禁止出现字段名、状态码、条款号这类开发口径

给人看的句子只说结果与下一步（「移出后他看不到本项目的任何内容，随时可以再请回来」）；表字段名、HTTP 码一律退回代码注释。实测中用户当面抓出过一整族这类文案 —— 这是真付过学费的。

## 🚚 运维与部署

### 为什么默认 SQLite、MySQL 并存，且开发期就双库持续验证

交付对象是 BIM 团队：SQLite 零配置开箱即用、备份 = 拷目录；团队多人共用或接入既有 MySQL 时一行配置切换。两套方言的坑（类型映射、时间形态）在开发期就持续撞，而不是交付时才发现。代价：表定义要互相对拍防漂移，SQLite 那侧不能用两边不通的类型形态；**SQLite 的库文件别放网络盘**，文件锁不可靠。

### 为什么外网加密不强制、反向代理不随包提供

平台不强制加密，任何地址形态都跑得通；建议外网部署者自备 HTTPS（口令与令牌明文过公网有窃听的实际风险）。反向代理那一档**拍板不做**：单进程一台内网，代理只带来一处要同步的体积上限。⚠️ 现场自己拉代理时的两条硬规矩：请求体上限必须高于「一整套模型 8 GB」那道合计闸（按合计定，不是按单件 200 MB —— 默认值只有 1 MB，一套模型当场撞线，且撞出来是一页 HTML 不是平台的错误提示）、并关掉请求体缓冲。

### 为什么配置没有热通道

「改环境变量要重启」是定案：那几颗指路径的开关都是启动时读一次的模块级常量，装机那天设一次，为低频动作做在线改配置要连带处理「改到一半正在跑的解析」。代价：界面探测、包内说明、部署文档三处载体必须同步口径，漏一处就漂（这句已经漂过一次）。

### 为什么端口只有一处定义

开发端口固定在框架配置里、生产端口由运行时认、配置模板里**不留那颗没人读的端口开关** —— 留着它最贵的代价是下一个人照着改、改完发现纹丝不动。端口统一 5555，不要另挑。

### 为什么「一整套 8 GB」的闸要按合计判、磁盘按 16 GB 留

单件 200 MB × 60 件 = 12 GB，数量闸罩不住体积合计。而覆盖式上传「先新后旧」：新那套还在暂存区时旧那套仍在正式位，**磁盘峰值是两倍** —— 部署机留盘按 16 GB 算。破线是整套作废，做不到提前拒。

### 为什么两类后台任务不建表（导出任务、解析状态）

建表要给它们配权限、生命周期与迁移，而这两类产物天然是一次性：导出用进程内注册表、解析状态写库旁的小文件。重启后没有任何端点还能指到旧产物，那些文件已是「链接已断而文件还在」—— 于是服务启动时清扫一次，这是**唯一有强判据的时机**；常驻 TTL 让「删文件」发生在没人看的时刻，出问题无从归因。代价：长驻期间导出产物只增不减、重启即清；跨实例看不到彼此（多实例部署前这四个清扫判据都要重议）。

### 为什么装完解析环境不自动补算

上传是全站唯一的解析触发点，口径 = **重传即重跑**。加一个重解析端点要新的权限判据、新的状态机分支，而覆盖式上传本来就在同一条码路上。代价明说：现场第一次装好环境的人一定会困惑「装了为什么不自己算」—— 所以这句必须同时写进部署文档、包内说明与界面话术三处。

### 为什么不用云 CI 而用本地 git 钩子

托管平台的云构建镜像 Node 版本过低，跑不动这套要求 22 的运行时。本地门禁（提交前秒级禁用字符自检 + 表定义对拍 + lint，推送前再加类型检查）效果等效且拦截更早。**永远不许用跳过钩子的参数把这道闸过成虚的** —— 钩子拦下来说明有真问题。

### 为什么会话用加密 Cookie、而会话里不装角色

前端 JS 读不到 HttpOnly Cookie，跨站脚本偷不走；自写 token 随意签发、本地存储能被偷。但它是**会话机制不是权限系统**，RBAC 仍靠自建。会话是登录那一刻的快照，角色会变 —— 管理员被降级后界面若读会话就会骗人（还显示入口）。纪律：会话只判登录态，一切业务资料每次实时取。

### 为什么没有自助注册、找回口令走管理员

内网小团队没有可依赖的第三方身份源；平台没存邮箱、没有发信的地方，自助找回天然无落点。代价两条：**重置会把那个人已登录的所有设备一起下线**，别手滑替别人点；至今没有登录失败锁定与验证码，现有手段只防凭据外泄、**不防爆破** —— 这一格未拍板，实名与否也还没定。

### 为什么装完库就能登录

默认平台管理员在建库时自动创建（幂等：已有管理员就跳过、不覆盖已有口令），不靠部署者记一条命令行 —— 「装完就要能登录」。代价：出厂口令写在脚本里，**交付前必须改掉**；本期不做首登强制改密。
