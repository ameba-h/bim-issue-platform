# 架构与技术选型

> 这一页讲整棵代码树的形状，以及**为什么是这个形状** —— 一次点击从浏览器出发，经过哪几层、哪些闸，回来又落在哪里。要改代码的人（无论前后端）先读这里。

## 🧭 一句话形状

**单仓库 · 单进程 · 全栈 TypeScript**：Nuxt 出前端那一层 SPA，同一个进程里的 Nitro 出 REST 接口，数据落在一个本地 SQLite 文件上（多人共享时才换 MySQL）。

没有第二个服务、没有消息队列、没有对象存储、没有独立任务机、没有反向代理要求。所有「后台动作」都是**本进程内的函数**，所有文件都在**同一个数据目录**里。这一句是理解全文的钥匙：**很多在其他架构里由基础设施兜的事，这里必须由代码自己兜** —— 幂等、留痕、临时区清扫、崩溃后的状态收口。

```
浏览器（SPA）
   │  会话 Cookie（HttpOnly，前端 JS 读不到）
   ▼
Nitro server（server/api/v1/**，一个「方法后缀」文件 = 一个端点）
   │  三道集中闸 → 凭据解析 → 权限断言 → 入参整形 → 事务（业务写 + 留痕）
   ▼
Drizzle ORM ──► SQLite（node:sqlite）/ MySQL（mysql2）
   │
   └──► 文件系统 data/（目录布局 + 先落盘后写库，收在一个 util 里）
```

## 🧰 选型的第一理由：零原生依赖

依赖口径只有一条：**纯 JS 允许，需要本机编译或下载平台二进制的模块禁止。**

为什么它是第一理由而不是「性能」或「生态」：主交付形态是**内网一台 Windows 机器上的绿色文件夹**，装的人未必有编译链、离线时连下载包都做不到。原生模块会让「换一台机器装不上」成为常态故障。

| 常见需求 | 本项目的选择 | 被替掉的那个 |
|---|---|---|
| SQLite 驱动 | Node 内置 `node:sqlite` + Drizzle 的 sqlite-proxy | better-sqlite3（要编译） |
| 口令哈希 | Node 内置 `scrypt` | bcrypt / argon2（要编译） |
| 图片解码缩放 | `jimp` + `@jsquash/webp`（WASM） | sharp（要编译） |
| 打包 ZIP | `fflate` | 原生绑定、`zip` 命令 |
| Excel / Word 产物 | `exceljs` / `docx`（纯 JS） | 任何 Office COM 调用 |
| 端到端测试 | Playwright + **系统里已装的 Chrome** | 只替掉「下载浏览器二进制」那一步 |
| 模型解析 | **可选的外部 Python**，缺了不拦上传 | 常驻 Python 服务 / 原生 ifc 绑定 |

⚠️ 一个连带后果：`node:sqlite` 是实验性内置模块，代码里**按需加载**（SQLite 分支里才取），不写静态 import —— 否则 MySQL 环境每次启动也吃一条实验性警告。这类「为了干净启动的小动作」在别处不会有。

## 📚 技术栈

| 层 | 用什么 | 说明 |
|---|---|---|
| 框架 | **Nuxt 4** 全栈单仓库 | `app/` = 前端，`server/` = 后端，`shared/` = 两边共用类型 |
| 渲染 | **SPA（`ssr: false`）** | 见下一节 |
| UI | Nuxt UI v4 + Tailwind CSS v4 | 组件前缀统一 `U`；页面壳（侧栏、顶栏、布局）基于官方 **Nuxt Dashboard 模板** 搭建 |
| 表格 | `@tanstack/table-core` | 经 `UTable` 的 `tableApi` 暴露，不另引 Vue 适配层 |
| 图表 | `@unovis/vue` | 只服务首页那四张图 |
| 日期 | **不引日期库** | `Intl.DateTimeFormat('zh-CN')` + `formatTimeAgo`，全落在 `app/utils/format.ts` 一份里（含「无时区后缀按 UTC 补齐」的兜底） |
| 鉴权 | `nuxt-auth-utils` | sealed 加密 Cookie（HttpOnly），前端 JS 读不到凭据 |
| 数据 | Drizzle ORM 0.45 + `mysql2` | 双方言两份 schema，由 `pnpm db:check` 对拍 |
| 校验 | `zod` 4 | 入参整形与 MCP 工具的参数描述共用一套 |
| 富文本 | `marked` + `dompurify` | 项目说明显示时渲染，**存储的是 Markdown 原文** |
| 对接 | `@modelcontextprotocol/sdk` | MCP 薄壳 |
| 运行时 | Node.js ≥ 22 + pnpm（`nodeLinker: hoisted`） | 不用 npm / yarn，避免两套锁文件 |
| 开发端口 | **5555** | 定义**只在 `nuxt.config.ts`** 的 `devServer.port` |

三条既有约定：界面文案**中文硬编码**，不引 i18n；时间**入库统一 UTC、出接口 ISO8601 带 `Z`**，转本地由前端做；问题详情走**右侧抽屉**而不是独立路由页（为了粘贴截图时手里那条不丢）。

## 🖥️ 为什么是 SPA，以及它连带决定了什么

采用的理由只有两条：**后台系统没有 SEO 需求**；**单执行路径、无登录闪烁**。真正要写进架构的是它带来的五个连带后果 —— 前四个是机制，第五个是纪律：

- **`useFetch` / `useAsyncData` 的核心价值归零**：它们的收益在「服务端预取 + 跨端复用」，SPA 下都不存在。取数统一走 `$fetch` + 自管状态。官方也明确：**`await` 与 `lazy` 是无效组合**；
- **未匹配的 `/api/**` 会落到页面兜底、渲染出一段 HTML 且状态码 200** —— 「接口地址写错」看起来像成功。为此专门有一份兜底路由：把 `/api/**` 下没命中的路径打回 **404 且刻意不带 `error.code`**（契约的判别规则是「只有业务错误才带 code」，否则前端会把「地址写错」显示成「项目不存在」这类业务文案）；
- **模块级单例天然成立**：`useState` 在 SPA 下就是模块级 ref，跨页共享、刷新即重置（正是想要的语义）。⚠️ 同一前提是「不开 SSR」—— 一旦打开，模块级在途句柄和缓存会跨请求串味；
- **客户端导航 = 全部导航**，守卫逻辑只有一条路径要照顾；
- **前端判权只是体验**：所有显隐判断跑在用户那边，**服务端必须逐请求独立校验**。

## 🗂️ 目录形状

| 目录 | 里面是什么 |
|---|---|
| `app/` | 前端：11 个页面 · 四个业务组件目录 · composable · 纯函数工具 · 全局中间件 · 布局壳 |
| `server/` | 后端：端点文件 · `utils` · `database` · 启动插件 · 两份 Drizzle 配置 |
| `shared/types/` | 按域拆的接口形状定义，前后端共用一份。**后端可加成员；删成员要核零引用**；类型对不上在这一层对齐，不让前端就着后端实现改 |
| `scripts/` | 建库迁移 / 文档门禁 / 绿色包 / IFC 转换器 / 建号 |
| `tests/` | `tests/server/` 服务端单测 · `tests/e2e/` 界面端到端 |

四条容易踩的越界：不要在 `server/api/` 里加临时 mock 端点（缺端点就对着契约写，界面显示空态并写明原因）；不要替对方「顺手修」另一侧的实现；共用目录的既有内容改动前先确认；改动边界按目录所有权走。

## 🚪 一次写请求在服务端经过什么

```
浏览器 / AI 客户端
  → h3 路由（一个「方法后缀」文件 = 一个端点）
  → defineApiHandler 包装，进端点之前依次三道集中闸：
      通道闸 —— 这枚凭据能不能走这条路、这类动作经不经得起 AI 代执行
      空字符守卫 —— 请求体带 NUL 的一律拒（先定「谁能写」，再定「写的内容能不能要」）
      项目冻结写闸 —— 在进端点之前拦，免得做完一堆查询才撞 403
  → 端点内：凭据解析成主体 → 逐请求权限校验（角色 + 对象状态）→ 入参整形与未知字段拒绝
  → 事务：业务写 + audit_log 留痕（唯一写入口）
  → 文件动作一律在事务外（先落盘后写库，失败回滚并删掉本次已落的文件）
  → 响应（成功直接是负载；失败 = { error: { code, message, details? } }）
```

这一层里六件不显然的事：

- **错误出口是包装器而不是全局 errorHandler**：契约要求框架 404 / 未捕获异常**必须没有 `error.code`**，用包装器天然满足 —— 业务错误在这里成型，其余异常原样抛给 Nitro；
- **三道闸落在包装器里，不散进各端点**：散着判必漏，漏一个就是「冻结了还能写」；集中一处，**新增端点默认就落在闸内**。冻结闸只拦写方法、两条放行例外（导出子树与改派负责人）、项目查无此行不拦（404 归各端点）；代价是每个项目写请求多一次点查；
- **错误码是字符串常量，不是数字**：服务端冻结 45 枚，HTTP 状态码只是配给它的语义 —— 判业务分支先看响应体有没有 `error.code`；
- **留痕只能从一个函数写**：`channel` 只取决于凭据、不该由端点自己填（否则 AI 接入后留痕全线谎报成人干的）；代理执行三个身份字段散着填迟早漏一个；**空 diff 不落行**；
- **幂等键作用域是（操作者, key）**：首次执行落一行并记请求体 SHA256；重放且指纹相同原样返回，不同则 409 拒 —— 这层存在的唯一理由是「网络抖动重试和用户多点一次，服务端必须认得出这是同一个逻辑操作」；
- **分页与排序是白名单制**：`pageSize` 超限**报 422 而不是静默截断**（截断会让调用方以为拿到了全量）；排序白名单外**报错而不是忽略**。

## 🔑 凭据、主体与 AI 通道

两种凭据、**同一个主体**：浏览器是 sealed 加密 Cookie，脚本和 AI 是 Bearer Token。服务端把两者解析成同一个 `subjectId`，**权限判定层不需要知道来的是哪种凭据**。

三条硬口径：

- **带了 `Authorization` 就完全走令牌通道，绝不回落到 Cookie** —— 否则「令牌打错的脚本」会静默改用浏览器留下的会话，查出别人的数据还报告成功；
- **AI 不持有任何凭据**：只有「代理执行」= 人的令牌 + 进程内通道密钥，「是不是 AI 通道」由服务端验，客户端自报身份一律无效；
- **AI 的权限 = 发令人权限 ∩ 该项目允许 AI 的动作**，留痕记三个人并把通道标成 `ai`。

## 📡 前端那一侧：三层取数与一张状态登记表

**分域封装**：11 个 `useXxxApi`（问题 / 项目 / 成员 / 我的 / 答复 / 文件 / 导出 / 审计 / 管理 / 模型 / 底层 `useApi`）。页面只调语义化方法，**不碰路径字符串** —— 路径或字段变了只改一处。文件域、导出域、模型域必须单独一个封装：上传是 multipart、取图是 blob、导出是流式下载 + 任务轮询、**模型上传连 `fetch` 都不用**（改用原生 XMLHttpRequest —— 字节级进度只有 `xhr.upload.onprogress` 给得出来）。

`useApi` 负责四件事：拼前缀并注入当前项目 ID；解包与失败整形；按 `error.code` 翻译与分派；幂等键透传。

⚠️ **幂等键不在这一层生成**。它的生命周期是「一次用户操作」而不是「一次 HTTP 调用」—— 由发起操作的表单 / 抽屉那层生成并持有，重试复用、改了内容才换。每调一次现生成 key，重试就带新键、服务端认不出重复 → **重复建问题**，而这个 bug 只在网络抖动时暴露。

⚠️ **生成键那行必须在非安全上下文也跑得动**：`crypto.randomUUID()` 规范上只在 https 与 localhost 存在，而主交付形态是**内网 http 直连**，那里它是 `undefined`。所以用 `crypto.getRandomValues` 手拼 —— 幂等键要的是唯一，不是密码学不可预测。同一类坑在剪贴板上也踩过（内网 http 下 `navigator.clipboard` 不存在，故两段式降级）。**凡是浏览器 API，都要先问一句「内网 http 下它在不在」。**

**状态：`useState` + 登记表，不引 Pinia、不引 vue-query**。全局状态只有四类：会话、当前项目上下文、类目全量、少量 UI 条件。key **必须集中登记**，禁止页面随手起 —— 否则同一份数据两个 key、两处各自拉取。三条配套纪律：

- **派生值不另存一份**：当前项目、我的角色都是从 `me` 派生的 computed，唯一可变源只有一份，就不可能出现「切换器与判权读到不同项目」的分裂；
- **会话只判登录态，业务资料从 `me` 取**：从会话里读角色等于读登录那一刻的快照 —— 管理员被降级后界面还会显示入口；
- **取数的触发点只允许一个**：薄封装内部 watch 是唯一触发源，页面不得再 watch、不得手动 refresh —— 两个触发点会让一次筛选变化打两个请求。

**当前项目不进 URL、筛选条件也不进 URL**（同一取向，用户裁决「刷新丢可接受」）。明确接受两条代价：**后退键直接退出列表页**、**链接不能复现筛选结果**。项目上下文是**账号级**状态（存服务端），不是标签页级 —— 多标签页各持一个项目不做（接受），跨设备自动同步视为特性。

**图片一律过鉴权**：四类图都用 blob 拉回、`createObjectURL` 绑、卸载时释放。不直接填 `<img src>` 的理由不是「带不上 Cookie」（`<img>` 会带同源 Cookie），而是三条：失败不可控（401/403/404 回的是 JSON，`<img>` 只显破图，分不清「无图 204」与「无权 403」）· 没有加载态与占位 · 错误处理要落进同一套按 code 分派的口径。**不做缓存**：内网 + 本地服务下重复下载的感觉为零，而缓存一引入就得管销毁时机，时机错了是内存泄漏。

## ⚖️ 判权为什么写两遍

前端 `app/utils/permission.ts`：17 个语义化判定函数 + 平台管理员判定 + 对象状态判定 + 一份「跟项目走」的路径清单，**页面不写裸的角色比较**。唯一依据是「当前项目内的角色」—— 平台角色只决定「平台管理」那一个入口的显隐（两个都叫 role 是最早的坑，契约层已改名 `platformRole` 规避）。

四条纪律：**隐藏按钮，而不是禁用按钮**（甲方是外部用户，一排灰按钮只会反复来问「为什么不能点」；禁用态只留给「已关闭不能编辑」那一类，且旁边必须写明那句话）；**批量入口只按角色粗判、选中行逐条精判**（代价是提交后必须逐条展示结果，不得只弹一句「已处理」）；**前端判权不是安全边界**（服务端返回了前端认为不可能的权限码，按前端 bug 处理）；两个易漏方向 —— 专业负责人在项目内**不分专业**（前端不得按专业做过滤或隐藏）、已关闭只锁编辑字段**不锁删除**。

降级方向也有讲究：**列表类宁缺毋滥**（认不出的角色丢掉整行，假角色会把人提成管理员显示），**留痕类宁多勿少**（认不出的动作只降级成空并保留整行，少一行留痕比多一行难查）。

## 🗄️ 数据层：一个文件、两份 schema、四份定义

`DATABASE_CLIENT` 二选一：`sqlite`（交付默认，内置驱动、零安装）/ `mysql`（多人共享实例时用）。

三条结构性纪律：

- **表只从 `server/database/tables.ts` 取**：SQLite 与 MySQL 是两套表定义，混用不报错但**静默出错**（同一列一边按 text 映射、一边按 DATETIME 映射）；
- **时间转换只在一处**：出接口一律 `toIsoUtc`，写库前一律 `toDbTime` —— 业务代码自己 `toISOString()` 直接入参，是双库形态差异最常见的入口；
- **四份表定义互相对得上**，由 `pnpm db:check` 静态对拍（不连库）：14 张表 / 136 列 / 35 索引 / 31 外键 / 16 CHECK。它是提交闸门之一，改表那一轮跑不过就提交不上去。

⚠️ SQLite 侧每次连接都要做的一件事：`PRAGMA foreign_keys = ON` 是**连接级**不是库级设置 —— 不执行它，SQLite 会静默忽略所有外键，跨项目隔离直接失效。还有一处刻意的形状：`db` 对象在类型上借 SQLite 那一套用（两套泛型的并集会报错），代价是 MySQL 特有报错不会被类型系统提前发现，由单测与联调兜。

## 📁 文件层：两条落盘路，别混成一条

**第一条是附件、封面、头像**（storage util）：文件名 = 记录 ID + 扩展名（原始名只进库不进路径，防路径注入与重名）· **先落盘后写库**（真实 I/O 禁止进数据库事务）· 存储路径存相对路径且**绝不下发给前端**（取图走鉴权端点，下载带 attachment 头，`data/uploads` 从不静态暴露）。

**第二条是 IFC 模型**，不复用第一条的三个结构性理由：

- **体积**：框架自带的 multipart 读法是全量缓冲，单件 200 MB × 最多 60 件等于把 12 GB 塞进一个进程 —— 所以模型那一发**自己接流**：`busboy`（纯 JS、零原生编译）解析，每个 part 直接管道进磁盘，边写边算 SHA256；
- **判型**：IFC 是 STEP 文本，判据是首个非空行以 `ISO-10303-21;` 开头 —— 硬塞进图片白名单会污染附件判型；
- **删除语义相反**：附件软删、磁盘永久保留；模型**硬删**，删记录也删盘上文件。

落盘还多一段暂存：先进 `.incoming/<项目>/<批次>/`，整套校验通过才改名进正式位。链路的完整口径（三道尺寸闸、合计闸、解析与状态四态）见第八页与部署页。

## ⚙️ 进程内的后台动作：四个启动清扫 + 两类任务

四个插件都在服务启动那一刻跑（`server/plugins/`），判据是同一族的：

| 插件 | 收掉什么 | 为什么安全 |
|---|---|---|
| exportSweep | 上一次遗留的导出产物 | 任务表是进程内的，重启后没有任何端点还能指到旧产物 —— 那些文件是「链接已断而文件还在」 |
| incomingSweep | `.incoming/` 里的半截上传 | 新进程起来意味着上一进程的上传已中断；只扫那一个目录，结构上不可能误伤正式位 |
| parseReap | 状态旁文件里还写着「解析中」的轮次 | Python 进程活不过重启，不标失败界面就永远转圈；只写状态，解析库一个字节不动 |
| idempotencySweep | 过期幂等键行 | 读侧本来就惰性失效，这里纯回收空间；唯一常驻的定时任务（每 24 小时，不阻止退出） |

⚠️ **为什么不做常驻 TTL**：常态是内网一台机一跑几个月，让「删文件」发生在没人看的时刻，出问题无从归因；启动那一刻是**唯一有强判据的时机**。代价也写清楚：**长驻期间导出产物只增不减，重启就是清理**。多实例部署前这四个判据都要重议（现在都假定本机只有一个进程共用这份数据目录）。

**两类「后台任务」都不建任务表**：导出用进程内注册表（任务 ID 重启即失效，轮询拿到「不存在」属正常）；IFC 解析用一次性子进程 —— 转换器跑完就退，产物是一个可直查的 SQLite 库，此后画像只查库不再调 Python（毫秒级），状态写库旁边的旁文件。**Python 是可选依赖**：起不来不算上传失败，原始文件照样落盘登记。

## 🔌 对接层：REST 是唯一入口，MCP 只是薄壳

17 个 MCP 工具与 17 条契约端点行 **1:1 映射**，转发就是同进程里打自己那一发 REST（凭据原样带上）。纪律三条：**不 import 服务层、不查库、输出原样透传不做映射层**。鉴权、权限、冻结闸、幂等、留痕全部由 REST 那层照咬 —— 所以 REST 改字段或规则时，这一层最多改工具描述里的口径，**不改逻辑**。工具清单与令牌通道在 [MCP 接入](/mcp/access) 那两页。

## 🚫 这套架构刻意不做的选择

| 不做 | 为什么 |
|---|---|
| Pinia | 全局状态只有四类，没有一类需要它的体系；将来真复杂了调用点可平滑替换 |
| `@tanstack/vue-query` | 取数就是「进页面拉一次、操作后重拉」，没有缓存失效 / 去重 / 聚焦重取的需求；多学一套心智模型，收益为负 |
| SSR | 见「为什么是 SPA」一节 |
| i18n | 中小团队中文界面，文案硬编码 |
| PDF 导出 | 问题数量一多，PDF 体积就会很大；带图 HTML 包解开后用浏览器打开、直接打印成 PDF —— **这一转已经交给浏览器，服务端不必再造一档**（真做 PDF 那档还得引排版引擎） |
| `export_jobs` 任务表 | 进程内注册表足够，且「重启即失效」正好让启动清扫有强判据 |
| 对象存储（S3） | 单进程单目录；落盘只把「目录布局 + 先落盘后写库」收成一个 util —— **没有 provider 接口，也没有第二家实现**，真要换存储时再抽 |
| 常驻 Python 服务 | 一次性子进程 + 落一个可直查的 SQLite 库，比养进程简单得多 |
| 前端假数据层 | 会与契约漂移且容易忘记删；缺端点就显示空态并写明原因 |
| 浏览器里的三维模型展示 | **规划项，以后要做，目前零实现**（渲染依赖都还没引入）。注意它与「IFC 画像」是两回事：画像看的是解析出来的统计数（构件数、楼层、类别分布），像一份体检报告；三维展示是看模型本身 —— 各自推进，别互相代称 |
| 列自定义 / 消息通知 | 定案不做（前者代价大于收益，后者不建第二套「消息中心」心智，要看变化去操作记录） |
